# MEDWELL CLINIC SYSTEM Upgrade Risk Register

| Risk ID | Category | Description | Likelihood | Impact | Mitigation Strategy |
|---------|----------|-------------|------------|--------|---------------------|
| R001 | Data Integrity | Existing unfinished queues (e.g. at pharmacy) fall out of the standard workflow during migration. | High | High | Map all ambiguous legacy queues to `migration_review_required`. Provide a dedicated dashboard for the Admin to manually resolve these edges cases. |
| R002 | Concurrency | Generating atomic document numbers (HN, receipt, medical certificate) simultaneously causes duplicate IDs. | Medium | Critical | Utilize PostgreSQL atomic operations (e.g. sequences, `FOR UPDATE` row locks, advisory locks). Perform load testing with 100 simultaneous requests. |
| R003 | Security | Users with old roles retain excessive privileges or escalate their roles via API manipulation. | Low | Critical | Ensure Google sign-in UI choices are strictly validated at the Edge Function layer. Use RLS on all Postgres tables. Do not auto-migrate powerful roles like Doctor; require Admin approval. |
| R004 | Security | External API keys (Google Translation, Gemini) are exposed to the public via frontend JavaScript or unrestricted endpoints. | Low | Critical | Store keys purely in Supabase Vault / Edge Function environment variables. Never return them to the client. Apply rate limiting and RLS to the translation endpoint. |
| R005 | Application | Server-side PDF generation fails to render Thai characters correctly (vowels, tone marks). | High | Medium | Use a proven library (`pdf-lib`) and embed specific Thai fonts (e.g., TH Sarabun New) directly into the Edge Function assets. Verify via automated and manual PDF visual tests. |
| R006 | Synchronization | Offline clinical drafts overwrite newer changes made by another user or device when internet is restored. | Medium | High | Track `last_synced_at` and `device_id`. On reconnection, check server state. If conflict detected, launch the conflict resolution modal UI rather than blind overwriting. |
| R007 | Rollback | Production database migration encounters an error halfway through the sequential scripts. | Low | Critical | Conduct full rehearsal on staging. Ensure Supabase Point-in-Time Recovery (PITR) or an immediate `pg_restore` from the pre-migration `pg_dump` can be executed within the maintenance window. |
| R008 | Compliance | Issued medical certificates are altered after printing, causing legal or auditing discrepancies. | Low | High | Certificates are immutable once `issued`. Replacements require voiding the original and generating a new sequence number, logging the reason and reviewer. |
